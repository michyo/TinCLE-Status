TinCLE Engine Feedback (udanrica)
==================================

Scope
-----
- Target: tincle_core, TinCLE v0.18, 32-bit Windows build (tinclec 32-bit)
- Area: Direct SDL_Renderer drawing from a state draw callback
  (tincle_get_renderer() + SDL2_gfx / SDL render calls)

Observed Limitation / Issue
---------------------------
On the v0.18 32-bit Windows build, output from direct SDL_Renderer
drawing calls made inside a state draw callback never appears on
screen, while TinCLE API drawing in the same callback works.

Minimal reproduction (single-state 2D program, 640x480,
TINCLE_MODE_2D_NORMAL):

  void play_draw(void) {
      SDL_Renderer* r = tincle_get_renderer();
      tincle_clear((TinCLE_Color){20, 20, 40, 255});            // visible
      boxRGBA(r, 270, 200, 370, 360, 255, 170, 0, 255);         // NOT visible (32-bit)
      tincle_set_font(g_font);
      tincle_draw_text_center("Hello", 320, 180, white);        // visible
  }

Verified behavior matrix (same source, same machine):
- v0.18 64-bit build: all drawing visible, including boxRGBA.
- v0.16 64-bit build: all drawing visible, including boxRGBA.
- v0.18 32-bit build: tincle_clear and tincle_draw_text_center are
  visible; boxRGBA output is not visible.

Bisection results on the 32-bit build (all with no change):
- Not an argument-evaluation issue: hoisting computed arguments
  (e.g. 200 + bob) into named local variables first does not help.
- Not specific to SDL2_gfx: SDL_SetRenderDrawColor +
  SDL_RenderFillRect on the same renderer is equally invisible.
- Not a renderer-acquisition timing issue: caching the return value
  of tincle_get_renderer() in game_load (the pattern used in the
  SKILL.md sample) and using the cached pointer in the draw callback
  does not help.

This contradicts the documented contract: SKILL.md lists
tincle_get_renderer() as "Returns native SDL_Renderer* for direct
SDL2/SDL2_gfx primitive drawing" and the official sample draws
SDL_RenderFillRect / filledEllipseRGBA / filledTrigonRGBA inside
play_draw. That documented usage silently produces no output on the
32-bit build only.

Proposed Solution
-----------------
1. Investigate the 32-bit build's renderer/present path: whether the
   SDL_Renderer returned by tincle_get_renderer() on 32-bit is the
   renderer that is actually presented, and whether any internal
   compositing step after the draw callback overwrites direct draws.
2. If direct renderer drawing cannot be supported on the 32-bit
   build, state that limitation explicitly in SKILL.md (API table
   entry for tincle_get_renderer and the native-extension section),
   so code generators do not emit silently invisible drawing code.
3. As a supported alternative for simple shapes on all builds,
   consider adding a small TinCLE API helper, e.g.:
     void tincle_draw_rect_filled(int x, int y, int w, int h,
                                  TinCLE_Color color);
   so that basic rectangle drawing does not depend on the raw
   renderer path.
